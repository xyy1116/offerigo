# 邮箱投稿功能模块 · 设计方案（待评审）

> 状态：方案草案，待用户评审确认后进入开发
> 定位：求职简历投递深化；系统作为接收方平台；回执采用「自动邮件回执 + 站内通知回执 + 处理结果通知」三种

---

## 一、需求定位与范围

将现有「投简历-邮箱渠道」从**链外一次性 `mailto:` 操作**，升级为**系统内可追踪的邮箱投递全流程**：

- 投稿者在系统内提交标准化投递内容；
- 系统通过自有 SMTP 代发到企业招聘邮箱，同时**作为接收方**留存投递记录、接收回执/退信；
- 投稿动作触发自动回执（邮件 + 站内通知），处理结果触发结果通知（邮件 + 站内）；
- 平台/企业可在后台管理收到的投递内容。

### 核心闭环（一图流）

```
求职者点击「投简历」(邮箱渠道)
   → 填写/确认投稿内容（发件邮箱 + 正文模板 + 简历附件）
   → 系统生成投递记录(status=待发送)
   → 系统 SMTP 代发 → status=已发送
   → 系统自动回执「投递已提交」(邮件 + 站内通知)
   → 后台查看投递记录，录入/接收企业回执与处理结果
   → 推送「处理结果通知」(邮件 + 站内)
```

## 二、现状梳理与缺口清单

### 现有逻辑（仅 4 处）

| 项 | 现状 |
|---|---|
| 入口 | 岗位卡片「投简历」→ 双渠道弹窗（官网 / 邮箱） |

| # | 功能点 | 现状 | 目标 |
|---|---|---|---|
| 1 | 投递内容模板化 | 主题固定、正文手动 | 结构化正文模板 + 简历内容自动填充 + 附件自动挂载 |
| 2 | 系统代发 | 无 | SMTP 代发，用户无需打开本地邮件客户端 |
| 3 | 投递记录持久化 | 无 | 新增投递记录表，全量留存 |
| 4 | 自动回执（提交确认） | 无 | 邮件 + 站内通知 |
| 5 | 处理结果通知 | 无 | 邮件 + 站内通知 |
| 6 | 后台投递管理 | 无 | 列表/筛选/状态流转/回执录入 |
| 7 | 系统邮件配置 | 无 | SMTP/发件人可配置 |
| 8 | 站内通知体系 | 无 | 通知表 + 前端铃铛入口 |
| 9 | 用户分型适配 | 无 | 个人求职者 / 小企业用户差异化 |

## 三、用户角色与适配方案

| 角色 | 含义 | 专属优化 |
|---|---|---|
| **个人投稿者** | 求职者，投递简历 | 一键投递、简历附件自动生成、回执与进度站内可见、我的投递记录页 |
| **小企业用户** | 招聘方 / 小型 HR（无自有 ATS） | 后台投递管理页简化（收件→看简历→标记意向/拒绝），岗位邮箱自助配置，批量导出 |

> 小企业典型痛点：无专业招聘系统，只能用邮箱接收简历、记录零散。适配方案 = 系统充当轻量「收件箱 + 简历台账」，投递记录自动归集到对应岗位卡片下。

## 四、完整流程设计

### 4.1 投稿入口
- 保留现有「投简历」按钮与双渠道弹窗。
- 邮箱渠道由原来的「复制邮箱 + 唤起客户端」两个按钮，升级为「**提交投稿**」主流程（复制邮箱作为辅助保留，可配置开关）。

### 4.2 邮箱地址配置
- **收件邮箱**（企业方）：`target_job.email`（已有），未填提示补填，补填写回岗位库（沿用现有）。
- **发件邮箱**（系统代发）：系统级 SMTP 配置（后台可配），投稿者无需配置。
- **回执邮箱**（投稿者）：默认取简历 `BasicInfo.email`，可手动改。

### 4.3 投稿内容提交规范
- 主题：`应聘 [岗位名称] - [姓名]`（沿用现有，规范统一）。
- 正文：结构化模板，默认填充：`求职意向`、`自我介绍`、`核心技能`、`工作/项目亮点`、`联系方式`（取自简历素材库），投稿者提交前可编辑。
- 附件：系统自动生成简历（复用现有 `ResumeService.exportPdf / exportWord` 能力），可选附作品集。
- 提交前**预览确认**弹窗（与现有左右分栏预览风格统一）。

### 4.4 自动回执机制
分两个阶段（三种回执全部覆盖）：

1. **投递提交确认**（立即）：系统代发成功后，自动发邮件「你已成功投递 [岗位]，投递编号 xxx」+ 站内通知同步生成。
2. **处理结果通知**（后台触发）：后台将投递标记为「有意向 / 被拒 / 已归档」等状态时，自动向投稿者推送邮件 + 站内通知。

### 4.5 投稿内容后台管理
- 列表：投递记录（投递人 / 岗位 / 公司 / 收件邮箱 / 投递时间 / 状态 / 回执状态）。
- 筛选：关键字、状态、日期范围、岗位类型；搜索排序分页。
- 状态流转：待发送 → 已发送 → 已回执 / 被拒 / 已归档 / 退信。
- 回执录入：手工录入企业回执内容，或系统自动接收（见技术选型）。

## 八、技术选型（重点待用户拍板）

> 当前项目**无任何邮件能力**，以下 3 项是外部依赖/成本决策，需先确认再开发。

### 8.1 SMTP 发信服务（必选）
- 方案 A：`spring-boot-starter-mail` + 免费 SMTP（QQ/网易/阿里企业邮）—— 零成本、易接入，但有发信频率限制。
- 方案 B：付费邮件服务（阿里云邮件推送 DirectMail / SendGrid / Postmark）—— 稳定、可送达率高、支持回执解析。
- 需提供：SMTP 服务器 / 账号 / 授权码 / 发件地址昵称。

### 8.2 企业回执接收（可选，决定闭环深度）
- 方案 A：**暂不做自动收信**，回执由后台手工录入（最简，先跑通主流程）。
- 方案 B：IMAP 轮询收件箱，自动匹配回执到投递记录（需收件邮箱凭证，有轮询延迟）。
- 方案 C：邮件服务商 inbound webhook（如阿里云推送/Postmark inbound），实时可靠、需付费配置。

### 8.3 后台管理操作者
- 平台运营统一管理，还是小企业用户自助管理自己的岗位投递？两者权限模型不同，需确认。

## 九、实施阶段划分（评审通过后执行）

1. **阶段一（MVP）**：邮件底座（starter + 配置表）+ 投递记录表 + 提交投稿接口 + SMTP 代发 + 自动回执（邮件 + 站内）+ 我的投递记录页。
2. **阶段二**：后台投递管理页 + 状态流转 + 处理结果通知 + 小企业用户适配。
3. **阶段三（可选）**：企业回执自动接收（IMAP/webhook）+ 批量导出 + 投递报表。

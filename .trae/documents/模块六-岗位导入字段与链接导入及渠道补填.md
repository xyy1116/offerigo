# 模块六：岗位导入新增必填字段 + 链接导入 + 投简历渠道补填适配 + 卡片字段展示

## Context（背景）
智能岗位匹配模块此前已支持岗位文档/粘贴导入与投简历双渠道（官网+邮箱，识别公司名/邮箱）。本次需求把「招聘单位、招聘邮箱」上升为岗位入库的结构化必填字段：
- 岗位导入（文件/粘贴/新增的链接导入）统一在预览弹窗收集「招聘单位」「招聘邮箱」两项，至少填一项才可入库；
- 投简历双渠道改为**直接读入库字段**判定可用性（不再二次识别公司/邮箱），置灰渠道支持点击补填并实时激活；
- 岗位管理卡片与编辑功能同步展示/修改这两个字段。

目标：数据来源单一化（入库字段为唯一权威来源），交互闭环补齐。

## 一、后端改动

### 1. 实体 & 数据库
- `backend/.../jobmatch/entity/TargetJob.java`：新增 `private String companyName;`（招聘单位）、`private String email;`（招聘邮箱）。
- `backend/.../common/config/KnowledgeTableInitializer.java`：在 `ensureColumns()` 中追加两条幂等迁移：
  - `target_job` 表 `company_name`（VARCHAR(255) DEFAULT NULL，位置 AFTER job_requirement）
  - `target_job` 表 `email`（VARCHAR(255) DEFAULT NULL，位置 AFTER company_name）
- `backend/sql/jobmatch.sql`：在 `target_job` 的 `CREATE TABLE` 追加 `company_name`、`email` 两列，并追加两条 `ALTER TABLE target_job ADD COLUMN ...`（与现有迁移注释风格一致）。

### 2. DTO / VO 加字段
在以下文件统一新增 `companyName`、`email`（String，可空）：
- `dto/AddJobRequest.java`
- `dto/UpdateJobRequest.java`
- `vo/JobImportVO.java`
- `vo/TargetJobVO.java`

### 3. 大模型提取增强
- `common/llm/QwenChatClient.java` 的 `extractJob`：
  - 系统提示词新增规则：`companyName`（招聘单位全称，原文无则空串，jobName 不得含公司名）、`email`（招聘邮箱，原文无则空串）。
  - JSON 输出结构追加 `"companyName":"…","email":"…"`，空参返回串同步补齐两项为空。

### 4. Service 接口与实现
- `service/JobMatchService.java`：
  - `addJob(...)` 增加 `String companyName, String email` 两个入参；
  - `updateJob(...)` 增加 `String companyName, String email`；
  - 新增 `JobImportVO previewJobByUrl(Long userId, String url);`
- `service/impl/JobMatchServiceImpl.java`：
  - `buildJobImport(...)`：解析 LLM 返回后设置 `vo.setCompanyName(...)`、`vo.setEmail(...)`；若 email 为空，用正则 `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` 从 `originalText` 兜底提取第一个邮箱（新增私有 `firstEmail` 辅助）。
  - `addJob`：对 companyName/email 做 trim，空串转 null 后写入实体（email 可做轻量格式校验）。
  - `updateJob`：同样 trim 并写入 companyName/email。
  - `toJobVO`：设置 companyName/email。
  - 新增 `previewJobByUrl`：用 Jsoup `connect(url).timeout(...).userAgent(...).get()` 抓取，正文取 `doc.body().text()`（或 `title` + 关键选择器文本合并，至少 `body.text()`）；抓取失败/内容为空时抛 `BusinessException("链接抓取失败或页面无有效内容，请更换链接或改用粘贴导入")`；成功则复用 `buildJobImport(null, text)`。

### 5. 控制层 & 新 DTO
- 新增 `dto/JobLinkRequest.java`：`private String url;`
- `controller/JobMatchController.java`：
  - `POST /jobs`：`addJob(...)` 调用追加 `req.getCompanyName(), req.getEmail()`；
  - `PUT /jobs/{id}`：`updateJob(...)` 追加 `req.getCompanyName(), req.getEmail()`；
  - 新增 `POST /jobs/preview/link`：`previewJob(request.getUserId(), req.getUrl())`。

### 6. 投简历渠道重构（直接读入库字段）
- `dto/ApplyChannelRequest.java`：新增 `private String email;`（保留 `jobId`、`companyName`）。
- `service/ApplyChannelService.java`：**重写为读库字段版**，删除 `extractCompanies/cleanCompanyName/firstEmail/searchCompanyEmail/pickRecruitEmail/urlencode/searchClient` 及 `qwenChatClient/objectMapper` 依赖、JSON/RestTemplate/EMAIL 相关 import。保留：
  - `recognize(userId, jobId)` → `buildIntent(loadJob(...))`；
  - `patch(userId, jobId, companyName, email)`：加载岗位，`hasText(companyName)` 则写回 `companyName`，`hasText(email)` 则写回 `email`，`updateById` 后 `buildIntent`；
  - `buildIntent(job)`：
    - `companyName=job.getCompanyName()`，`email=job.getEmail()`；
    - `portalAvailable=hasText(companyName)`，原因为空时 `"未填写招聘单位"`；
    - `emailAvailable=hasText(email)`，原因为空时 `"未填写招聘邮箱"`；
    - `portalUrl=portalLibrary.match(companyName, jobName)`、`searchUrl=portalLibrary.searchUrl(companyName, jobName)`（companyName 为空时两者为 null）；
    - `companyCandidates=emptyList()`、`emailSource=null`。
- `controller/JobMatchController.java`：
  - `POST /apply/channel`：改为 `applyChannelService.patch(userId, req.getJobId(), req.getCompanyName(), req.getEmail())`。
  - `CompanyPortalLibrary` 复用，不改。

## 二、前端改动

### 1. API
- `frontend/src/api/jobmatch.js`：
  - 新增 `previewJobByUrl(url)` → `POST /jobmatch/jobs/preview/link`（timeout 60000）。
  - 将 `applyChannelWithCompany` 语义更新为补填：`patchApplyChannel(data)` 仍 `POST /jobmatch/apply/channel`，请求体 `{ jobId, companyName, email }`。

### 2. `JobMatch.vue`
- **链接导入入口**（`panel-actions`，约 L80-82）：新增「链接导入」按钮，`@click="jobLinkVisible = true"`。
- **新状态**：`jobLinkVisible`、`jobLinkUrl`、`jobLinkSaving`。
- **新链接导入弹窗**（放在「导入岗位」弹窗附近）：URL 输入框 + 提交按钮「爬取并标准化」；提交调 `previewJobByUrl`，成功后 `openJobPreview(data)`，失败由拦截器提示。
- **预览弹窗**（L561-600）：
  - 底部新增「招聘单位」+「招聘邮箱」输入框，绑定 `pendingJob.companyName` / `pendingJob.email`。
  - 底部提示与按钮：两字段均空时「确认添加」`disabled`，并显示「请至少填写招聘单位或招聘邮箱，方可添加入库」。
  - `confirmJobPreview`（L1732）增加校验（至少一项非空）与 `addJob` 传参（`companyName`、`email`）。
- **岗位管理卡片**（L484-502）：岗位名称下方新增两行弱化字段：`招聘单位：{{ item.companyName || '未填写' }}`、`招聘邮箱：{{ item.email || '未填写' }}`。
- **编辑弹窗**（L603-617）：新增「招聘单位」「招聘邮箱」输入框；`openJobEdit`（L1799）预填两项；`submitJobEdit`（L1808）提交含 `companyName`、`email`。
- **投简历双渠道弹窗**（L870-929）：
  - 官网置灰原因改为「未填写招聘单位」，邮箱置灰原因改为「未填写招聘邮箱」；移除 `emailSource==='search'` 提示分支。
  - 置灰渠道整体可点击 → 唤起补填弹窗 `openApplyPatch('company'|'email')`（可用渠道仍走原 `openPortal`/`copyEmail`/`openMailClient`）。
  - 移除顶部 `apply-company` 冗余展示逻辑中依赖公司来源的说明，公司名仅来自 `applyChannel.companyName`。
- **移除旧公司识别弹窗/逻辑**：
  - 删除 `companyInputVisible`/`companyInputText`/`companyChooserVisible` 状态（L1223-1226）；
  - 删除 L932-961 的「未识别到明确公司名称」「选择公司」两个弹窗；
  - `openApply`（L2204）改为：直接 `recognizeApplyChannel(job.id)` 拿 `data` 赋给 `applyChannel`，去掉 `handleApplyIntent`/`chooseCompany`/`confirmCompanyInput`/`matchWithCompany` 及其调用，去掉「未识别到明确公司名称」提示。
- **新增补填逻辑/弹窗**：
  - 状态：`applyPatchVisible`、`applyPatchField`（'company'|'email'）、`applyPatchValue`、`applyPatchSaving`。
  - `openApplyPatch(field)`：预填当前值并打开补填弹窗（标题随字段「补填招聘单位」「补填招聘邮箱」）。
  - `confirmApplyPatch()`：调 `patchApplyChannel({ jobId, companyName, email })`，成功后更新 `applyChannel`（渠道实时激活），关闭弹窗。
  - 新增补填弹窗模板（复用原 companyInput 弹窗结构改造）。
- **import 更新**：`api/jobmatch.js` 的引用由 `applyChannelWithCompany` 改为 `patchApplyChannel`，并新增 `previewJobByUrl`。

   - 三种导入预览弹窗均有单位/邮箱输入框且智能预填，两者至少一填才可确认；
   - 投简历按入库字段判定可用，置灰渠道点击补填实时激活并落库；
   - 官网/邮箱直接使用录入字段，不再二次识别；
   - 岗位卡片展示单位/邮箱，编辑可改；
   - 已有搜索/筛选/格式化/编辑删除不受影响。

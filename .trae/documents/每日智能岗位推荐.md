# 每日智能岗位推荐 — 实施计划

## Context（背景与目标）
当前系统已有「简历素材库 + 目标岗位库 + AI 岗位匹配排名」完整链路，但岗位来源依赖用户手动导入。本次新增「每日智能岗位推荐」：基于用户简历素材与求职偏好，每日 6:00 自动从招聘平台聚合匹配最适合的岗位，登录后可查看并一键加入目标岗位库（从而自然参与后续匹配排名、生成简历）。

经与用户确认的三项关键决策：
1. **数据源**：搜索引擎聚合 + 详情页抓取（不做四大平台直连爬取），来源平台按详情域名标注；失败自动降级。
2. **求职偏好**：新增独立 `user_preference` 偏好设置（意向岗位 / 期望城市 / 期望薪资），首次进入用「目标岗位库 + 简历 CareerGoal」预填。
3. **调度**：Spring `@Scheduled`（`0 0 6 * * ?`）单实例定时。

## 复用的既有能力（不重复造轮子）
- `JobLinkCrawler.crawl(url)`：URL→正文（静态 Jsoup → 动态 Playwright 降级），返回 `{text, reachable}`。
- `QwenChatClient.extractJob(text)`：招聘原文 → 结构化岗位（jobName/jobRequirement/companyName/email/techStack/jobType）。
- `JobMatchService.addJob(userId, ...)`：岗位入库，内部已含 AI 类型识别与 `clearCache`；推荐「添加」直接复用它。
- `KnowledgeEntry` + `loadKnowledge(userId)`：简历素材全量文本/结构化，作为匹配依据。
- `resume.dto.ResumeContent.CareerGoal`：`targetPosition/expectedSalary/workCity` 用于首次进入偏好预填（仅读取，不新增表）。
- `CompanyPortalLibrary.searchUrl` 的域名→来源思路，扩展为「推荐来源平台识别平台映射」。
- 控制器取用户：`JwtInterceptor` 已写入 `request.setAttribute("userId", ...)`，控制器沿用 `HttpServletRequest` 取 userId（见 `JobMatchController` 现有方法）。

## 数据模型（新增 2 张表，复用 KnowledgeTableInitializer 幂等迁移）
1. `user_preference`
   - `user_id` BIGINT（主键，账号隔离）
   - `target_position` VARCHAR（意向岗位）
   - `expected_city` VARCHAR（期望城市）
   - `expected_salary` VARCHAR（期望薪资范围）
   - `update_time` DATETIME
2. `job_recommendation`
   - `id` BIGINT 自增主键
   - `user_id` BIGINT
   - `job_name`、`company_name`、`location`、`salary`、`source_platform`、`job_requirement`（标准化的职责+要求全文）、`job_link`、`match_score`（DECIMAL，一位小数）、`recommend_date`（DATE）
   - `is_new` TINYINT（是否未读「新」标记）
   - `added` TINYINT（是否已加入目标岗位库）
   - `target_job_id` BIGINT（添加后回填）
   - `create_time` DATETIME
   - 唯一键建议 `uk_user_date_job(user_id, recommend_date, job_name, company_name)` 便于覆盖式去重。

## 后端改动

### 1. 求职偏好
- 新建 `entity/UserPreference.java`、`mapper/UserPreferenceMapper.java`、`service/JobPreferenceService.java`（含 GET/PUT）、`vo/PreferenceVO.java`、`dto/PreferenceRequest.java`。
- 首次读取（GET 无记录时）自动预填：意向岗位取 `target_job` 中出现频次最高的 `jobType`/`jobName`，城市/薪资取 `ResumeContent.CareerGoal`（能取到则取，取不到留空）；预填不落库、由前端显式保存后落库。
- `controller/JobMatchController.java` 新增 `GET /jobmatch/preference`、`PUT /jobmatch/preference`。

### 2. 搜索聚合器 `service/JobSearchAggregator.java`
- 输入：意向岗位、期望城市、（可选平台关键词），输出候选 `List<SearchCandidate{url, title, domain}>`。
- 用 Jsoup 直连搜索引擎结果页（Bing 优先，UA 伪装 + 中文 Accept-Language，短超时），解析结果标题与落地 URL，截断前 N（约 30）条，过滤非岗位相关域名。
- 每次刷新对「意向岗位」「意向岗位+期望城市」等 2~3 组查询并发抓取，结果合并去重 URL；请求失败/被反爬时返回已抓到部分，不中断。

### 3. 推荐服务 `service/JobRecommendationService.java`（核心）
`refresh(Long userId)` 主流程：
1. 取最新 `user_preference` + `loadKnowledge(userId)` 组合成简历文本。
2. `JobSearchAggregator` 出候选 URL。
3. 逐候选 `JobLinkCrawler.crawl(url)` → `extractJob(text)`；抓取失败/无有效内容跳过（best-effort）。
4. `平台识别`：URL 域名映射（boss/hrdidatacom → BOSS直聘、zhaopin → 智联、liepin → 猎聘、51job → 前程无忧、lagou → 拉勾等），兜底按域名当前后缀作为来源。
5. `去重`：按 `jobName + companyName` 去重（保留 match_score 更高一条）。
6. `匹配打分`：新增 `QwenChatClient.recommendScore(jobText, resumeText)`（复用 `chatJson(…, 0.0)`，输出 0-100 单值 + 一句理由），对候选打分。
7. `排序`：期望城市命中优先，次按 `match_score` 降序，取 Top 10。
8. `持久化`：按 userId 删除当日旧推荐，批量插入新推荐（`is_new=1`、`added=0`），`match_score` 保留一位小数。

`list(Long userId)`：返回该用户 `recommend_date=今日` 的推荐（按 score 降序），VO 含 `isNew`/`added`。
`addOne(userId, recId)`：读推荐 → 调 `JobMatchService.addJob`（把 `job_requirement` 作为岗位要求、`company_name` 作为招聘单位、`location/薪资/source` 并入要求文本或补齐）→ 成功后回填 `added=1` + `target_job_id`；已 `added=1` 直接幂等返回。
`addAll(userId)`：遍历未 `added` 推荐的顺序添加到目标岗位库。

### 4. 定时任务
- 新建 `jobmatch/task/JobRecommendScheduler.java`，`@Scheduled(cron = "0 0 6 * * ?")`。
- 注入 `SysUserMapper`（系统模块）遍历全部 userId（或注入一次性查全量用户的服务），逐个 `refresh(userId)`，单用户异常 catch 不阻断其他用户。
- 在 `ChuanApplication` 或新 `config/ScheduleConfig.java` 加 `@EnableScheduling`。

### 5. 控制器端点（JobMatchController 或新增 JobRecommendationController）
- `GET /jobmatch/recommend`、`POST /jobmatch/recommend/refresh`、`POST /jobmatch/recommend/{id}/add`、`POST /jobmatch/recommend/add-all`。

## 前端改动（`frontend/src/views/JobMatch.vue`）

### 1. 布局改造
- 将右列 `.top-grid` 的「目标岗位库」面板外包一层上下布局：上半段岗位库，下半段新增「每日智能岗位推荐」面板；左列「简历素材库」通高不变；下半区 `.result-panel`（AI 匹配排名）仍通栏全宽。
- 新增 `.right-stack` 容器（flex 纵向）与推荐模块样式，沿用紫白冷调设计规范 + `align-items: stretch` 等既有约定。

### 2. 推荐模块交互
- 模块头：标题 + 右上「刷新」按钮（手动触发 refresh，进入加载态）。
- 登录提示：`recommendations` 中任一 `isNew` 为真 → 顶部高亮提示「已为你获取到最新合适的岗位，快去看看！」。
- 列表：10 条按匹配度降序，每条展示岗位名称/公司/地点/薪资/匹配度/来源平台，点开展开详情（职责+要求）；每条右侧「添加到岗位管理」；底部「一键全部添加」。
- `added` 状态：按钮置灰显示「已添加」，不可重复添加。
- 偏好设置入口：模块头或岗位库区新增「求职偏好」编辑弹窗，字段=意向岗位/期望城市/期望薪资，保存调 PUT preference。

### 3. API（`frontend/src/api/jobmatch.js`）
新增 `getPreference`、`savePreference`、`listRecommendations`、`refreshRecommendations`、`addRecommendation(id)`、`addAllRecommendations`。

## 关键复用与一致性
- 推荐「添加」走既有 `addJob`，天然触发 `clearCache(userId)`，使后续「AI 岗位匹配排名」在数据版本变更后可见提示并重算——与既有「手动更新排名 + 指纹缓存」链路无缝衔接，无需额外打通。
- 推荐 `match_score` 为「轻量预评分」，仅供推荐排序；岗位入库后的正式匹配分仍由既有排名内核计算，避免两套口径冲突。

## 验证
1. 后端：`mvn.cmd -q -DskipTests compile` 无输出即通过。
2. 前端：`npm.cmd run build` 末尾 `✓ built in XXs`。
3. 手动触发 refresh（接口/刷新按钮）→ 返回 ≤10 条、无重复、含来源平台与匹配度、期望城市优先。
4. 单条添加 / 一键全部添加 → 岗位库出现对应记录、按钮变已添加、再点无效。
5. 偏好保存 → 下次 refresh 检索词变化。
6. 登录态切换两账号 → 推荐列表互不影响（userId 隔离）。
7. （可选）`@Scheduled` cron 断言：临时把 cron 改成近 1 分钟验证定时触发一次，再改回 `0 0 6 * * ?`。

## 风险与降级
- 搜索引擎/平台反爬导致某次 refresh 抓取量不足 → best-effort 返回已抓到部分，前端不报错、显示「本次更新获取 X 条」；完全无结果时保留上一日推荐。
- BOSS 等页面登录墙/JS 渲染 → `JobLinkCrawler` 动态渲染模式兜底；仍失败则跳过该链接。
